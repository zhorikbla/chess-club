# План разработки

1. Написать и запустить минимальный `Main`.
2. Из требований вывести минимальную предметную модель.
3. Написать `Player` и проверить создание объекта из `Main`.
4. Написать `Tournament`.
5. Написать главную сущность `Registration` и enum ее статуса.
6. Добавить коллекции и простейшие операции без базы данных.
7. Только после этого спроектировать таблицы PostgreSQL.
8. Подключить JDBC и написать репозитории по одному.
9. Вынести бизнес-правила в сервисы.
10. Собрать интерактивное консольное меню.

Минимальная модель выводится из ТЗ, а не берется из готового архива:

- `Player` — участник предметной области;
- `Tournament` — турнир, на который записываются;
- `Registration` — основная сущность, связывающая игрока и турнир;
- `RegistrationStatus` — обязательный по ТЗ enum.

Дополнительные роли, статистику, экспорт и сложную обработку SQL-ошибок будем
добавлять только тогда, когда базовый сценарий станет понятен.
